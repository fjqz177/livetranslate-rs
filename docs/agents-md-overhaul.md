## 二、方案裁决

### 2.1 四层指令体系

```
L0  AGENTS.md          常驻总纲：硬约束/命令/拓扑/路由表/速查/看板   每会话自动装载，预算两档：主体 ≤170 行/17KB、全文件 ≤210 行/22KB
L1  常青真源 docs/      README(看板+纪律) decisions(账本) distribution
                        gotchas(坑册,新) prompts/(七卡,新)            按 L0 路由表按需读
L2  工作包文档          活跃 ≤3 → 完工即 archive                      既有机制，不动
L3  机械门禁            precommit.ps1 六项 + CI + check_agents_health(新,第七项；触发面含 docs 路径)
L4  项目记忆            ZCode memory（跨会话长事实）                  交接卡规范其更新时机
```

### 2.2 设计原则八条

1. **分层装载**：注意力是稀缺资源，23KB 常驻会把致命约束稀释掉。
2. **一行一事**：每行一个可独立 grep/diff/守护的事实单元；表格优于长句。
3. **指令与史分离**：规则留正文，出生故事留 git、archive、gotchas 证据区。
4. **单一真源+指针**：同一事实只活在一处，其余全是指针；手抄=未来漂移（本包自己裁掉的就是第五处手抄）。
5. **路由表驱动**：按「场景→必读」取用，不要求通读；路由表是 L0 核心资产，也是卡的唯一索引。
6. **坑册触发词化**：按「你在做什么」索引（触发/症状/根因/对策/证据五段），不按事故编年；全本带依赖版本注记。
7. **机械 > 自觉**：能脚本断言的纪律不靠散文祈使；断言集合本身要过消融（不设与既有断言重复的检查）。
8. **健康预算 + 滚动值防腐**：预算进守护；时点数字标「滚动值」或不写死；登记区间这类「到货即过期」的写法禁入。

### 2.3 与既有体系的缝合

- **docs/README.md 纪律①修订（Q4）**：顶层 `*.md` 分**常青参考**（README / decisions / distribution / gotchas + prompts/，无完工条件、不计数）与**工作包文档**（健康态 ≤3）两类；修订只动条文①半句 + 长期文档表补两行，随施工一提交，不写流水账（纪律⑨）。**定稿文案（施工一直接替换）**——条文①改为：「**四个区**：`README.md`（本看板）｜顶层 `*.md` 分两类——**常青参考**（decisions / distribution / gotchas 与 `prompts/` 目录，无完结条件、不计数）与**工作包文档**（健康态 ≤3 份，完工即归档）｜`drafts/`（未拍板草稿，不入库，看板=AGENTS 待拍板块）｜`archive/`（完工决策史，只读，仅许修订注记与归档波次路径替换）」；长期文档表补两行：`gotchas.md`（大坑全书，G-编号，完结条件=项目终结〔实际永久〕）、`prompts/`（流程七卡，完结条件=项目终结〔实际永久〕）。
- **decisions.md**：本包裁决落 **ADR-x**（架构决策类；号随定稿发，届时 ADR 表尾+1 核对——按当前账本即 ADR-15，草稿期不预留）；登记行一句话见 §三·提交 1。落档路径先 docs/agents-md-overhaul.md，收口更新为 archive 路径（纪律⑤）。
- **gotchas.md 头注**：前缀 G-（slug 派生）；**只收坑**（触发/症状/根因/对策/证据五段），规则与约定不收（那些归 AGENTS/prompts）；条目带依赖版本注记；施工前置核对全库（含 archive）无 G- 前缀冲突（纪律⑥「全局唯一含 archive」）；出档引用带路径。
- **precommit / ci.yml / .githooks**：第七项三处同步 + **.githooks 触发面扩展**（docs 三路径入触发，修正案 1）。

### 附录 H · PS7-only 迁移案（Q9 裁决 2026-09-13；ADR-16 随定稿发）

**研究结论（全部官方来源，2026-09-13 核实）**：

1. Windows PowerShell 5.1 = **Windows OS 组件**，无独立 EOL——随所在 Windows 版本生命周期走（如 Win11 23H2 至 2026-11-10 随 OS）；**feature-frozen**：不再有新特性/功能性更新，只收随 OS 的安全补丁。Microsoft 官方建议新开发与自动化一律 PowerShell 7（[Migrating from Windows PowerShell 5.1 to PowerShell 7](https://learn.microsoft.com/en-us/powershell/scripting/whats-new/migrating-from-windows-powershell-51-to-powershell-7)；[Support Lifecycle](https://learn.microsoft.com/en-us/powershell/scripting/install/powershell-support-lifecycle)：7.6 LTS 支持至 2028-11）。PS7 与 5.1 并存安装、互不覆盖，官方定性迁移「simple, quick, and safe」。
