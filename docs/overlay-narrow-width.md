# 悬浮窗窄窗右缘裁剪修复（D-125）

> **本文是什么**：D-125 施工定稿——悬浮窗（WinId::Overlay）最小窗宽 480 下 row2_combos
> 右缘裁剪的摸底数据、根因与修复设计。工单 = issue #27（D-120 裁决 #5 预留的同病另案）。
> 收口后本文迁 `docs/archive/`。

## 一、摸底（headless 量化，2026-09-30）

方法：照抄面板侧溢出断言模式（`run_ui` + **真实内嵌思源链** + shape bbox 右/左缘扫描），
480×200 视口 × zh/en × 精简/完整 × 三场景（默认 / 长模型名 `SenseVoice-Small-int8-2026-03-25`
/ 长消息），3 帧收敛后扫描（探针全量数据见该提交的测试史）。

| 场景 | zh | en |
|---|---|---|
| 默认·精简 | 干净 | 干净 |
| 默认·完整 | 干净 | **右 +49.3（其中 combos 行实体可见裁剪 +37.1）** |
| 长模型名·完整 | **+91.5** | **+145.1** |
| 长消息·完整 | 干净 | +49.3（消息行被连带撑出 +33/+25） |

行级判定：row1 按钮行（en 最宽 ~229）、row2_checks 复选行（en 最右 306）都远小于
456 可用宽——干净；monitor_bar 有 `.max(60)` 兜底、统计行与消息区本就
`horizontal_wrapped`——干净。**唯一病灶 = row2_combos（模型/源语言/目标语言下拉行）。**

## 二、根因（G-39 同族第三形态）

egui 0.36 `ComboBox::width(w)` 只是**下限**：`combo_box.rs:360`
`actual_width = (选中文本 galley + icon_spacing + icon_size) .at_least(minimum_width)`，
且默认 wrap_mode = Extend（无穷宽排版）——选中文本变宽，下拉就跟着长：

- en 默认：源语言「auto - Auto Detect」galley 108.6 > 份额 59.4，目标「zh - 中文」
  50.4 > 46.4——源/目标两只下拉把行撑到 517.1（可见裁剪 +37.1）；
- 长模型名：模型下拉独长 ~250 → 行撑到 567.5（zh +91.5 / en +145.1）；
- **下游连锁污染**：行溢出把 Frame 内容 min_rect 撑宽后，下方 ScrollArea 的可用宽
  随之失真（en 消息区折行标尺从 442 涨到 500.7）——消息行「看起来没折行」其实是
  折行标尺被上游溢出改写，修上游自愈。

对照：Qt 原版 QComboBox 在 stretch 布局里天然 elide，行宽恒定——本病灶 =
egui 增长语义与 Qt 未对齐（G-39 前两形态为「横排不换行 + min 照搬 Qt」，本形态 =
「width() 是下限不是上限」）。

## 三、裁决（D-125）

issue #27 预授权菜单 =「有病灶则同款三层防线（抬最小宽 / 行改造 / 溢出断言测试）」；
用户 2026-09-30 明示「issue 全部解决」= 开工令。四项自主裁决按 D-122 先例（实机走查
可推翻）：

| # | 项 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 总策略 | **行改造 + 断言锁死，不抬最小宽** | 480×200 恰为原版 Qt 悬浮窗 minimumSize，保持零偏差；D-122 已证常数标尺不可靠；唯一病灶行改完 480 即自洽 |
| 2 | 下拉行为 | **份额帽（子 ui 钳宽）+ truncate** | Qt QComboBox elide 同款语义；宽窗下份额随 available_width 放大、文本完整显示；egui 原生省略号，禁手测文本宽（防两套标尺，D-122 单源精神） |
| 3 | 下游污染 | **不单独修** | 修 combos 行后容器不再被撑宽，消息折行标尺自愈 |
| 4 | 测试矩阵 | **zh/en × 精简/完整 × 默认/长模型名/长消息 = 12 组** | 三场景分别锁默认文案、下拉增长、消息折行三个失效面；复选行/按钮行顺带入册 |

## 四、设计

- `row2_combos`：三只下拉各套 `allocate_ui_with_layout(Vec2::new(份额,
  interact_size.y), left_to_right(Center))` 子 ui（份额帽 = 份额宽即子 ui
  max_rect）+ `ComboBox::truncate()`——truncate 的排版宽 = 子 ui 可用宽，galley
  超份额即截断加省略号，下拉外宽恒 = 份额。份额公式不动（0.44T−60 / 0.24T−50 /
  0.24T−50，Qt 3:2:2 stretch 遗产）。desired 高 = `interact_size.y`（标准控件位，
  实际推进按内容 min_rect）——**禁传 0**：0 高 + Align::Center 会把内容在整段
  剩余高度里垂直居中、纵向全线塌位（施工实证：420×140 视口下译文行被挤进零高
  ScrollArea 不产出图元；机械锁 = 既有 superseded_overlay_line_is_neutral 测试，
  见 §六）。
- 复选行 / 按钮行 / monitor / 统计行 / 消息区零改动。
- 新测试 `overlay_no_horizontal_overflow_at_min_width`（overlay.rs tests）：真实字体链
  （D-122 教训：默认字体度量是假标尺）+ §三 12 组矩阵 + bbox ±2.0 扫描（全透明图元
  跳过，面板侧同款豁免）+ 语言表并行互打重试环（D-120 评审同款）。

## 六、评审留痕与残余（2026-09-30 收口评审）

已收编：①**文档对齐**——本节 §四与 G-39 第三形态句的 desired 高由初稿的 0 更正为
`interact_size.y`（施工实证 0 高 + Align::Center 纵向塌位，`capped_combo` 注留痕）；
②**活性断言**——溢出测试补「每帧非豁免图元 ≥5 + longmsg 原文/译文行必产出」，堵
「零图元时横向断言恒真假绿」盲区。对抗式复核修正评审一处误判：把 desired 高改回
0 时本测试（480×200 视口）确实不红——塌位不达本视口病阈值；h=0 塌位的机械锁 =
既有 `superseded_overlay_line_is_neutral`（420×140 视口下译文被挤进零高
ScrollArea，实测即红），两锁互补不互替，测试注释已如实分账。

残余（评审 P3，裁决内接受、实机走查兜底）：

- 下拉**展开态弹层**不在锁面：egui 弹层内容强制 Extend 排版，长模型名弹层可超窗缘
  被窗体裁剪（Qt 弹层为独立窗口可出窗，观感有差；egui 全应用既有行为，非本病灶）。
- 三枚行标签随**用户自定义字体**变宽不在锁面（测试锁默认字体链）：份额随窗宽线性
  放大，极端字体下 480 或再溢出——悬浮窗不做面板式派生 min 是裁决 #1 的有意取舍。
- 子 ui desired 高 18 与旧自然高的纵向节奏可能 ±1~2px，走查项 4（zh/精简观感回归）
  覆盖。
