# 裁决请求卡——要用户拍板时的固定格式

格式（逐条、一屏内）：

| # | 问题 | 推荐 | 备选（≤2） | 代价 |
|---|------|------|-----------|------|

- 推荐必附一句理由；代价 = 选它要放弃/承担什么，不许空。

纪律：
1. 不确定意图先问齐再动工，别猜。
2. 待裁决的调研稿/方案稿不提交——docs/drafts/ 未跟踪放置，点头后再 docs 提交。
3. 用户裁决优先于既有方案：裁决会引入新政策，不视为对原方案的「偏离」。
4. 实施后逐条回报：做了 / 未做 + 为什么。
5. 裁决落档：新决策当场登记 docs/decisions.md（施工中新裁决 = 当场加行），下一个号 = 表尾 +1。

→ 拍板后：回 kickoff.md 立档开工；未拍板稿留 docs/drafts/ 不入库
