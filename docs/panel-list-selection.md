# 面板列表选中态可取消化（D-123）

> **本文是什么**：D-123 定稿文档。面板三处列表（翻译模型 / 缓存模型 / 字幕文字行）选中态从「只进不出的持久高亮」重定义为「页内临时操作焦点」，补齐四条取消通道，顺带修复缓存页「再点取消」死写回。用户 2026-09-30 截图报案 + 四条裁决拍板，裁决留痕见 §7。

## 1. 背景与病根（实证）

用户报案：字幕页文字行列表，点击选中后蓝色高亮永存——再点不消、切 tab 不消、无任何取消手段。

排查结论：**不是一个 bug，是三个列表共用的同款交互模式缺陷**。三处列表的选中态只进不出——点行只能置选中，全 UI 无任何取消通道：

- 翻译页模型列表 `model_selected`（`crates/lt-ui/src/windows/panel/translation.rs`，行点击只 `Some(i)`）
- 缓存页模型列表 `cache_selected`（`crates/lt-ui/src/windows/panel/data.rs`）
- 字幕页文字行列表 `line_selected`（`crates/lt-ui/src/windows/panel/subtitle_page.rs`，即截图受害面）

行为来源：原版 Qt QListWidget 单选模式就是「再点不取消、切 tab 不清」，Rust 版为忠实复刻；阶段二以产品体验为准，按前端惯例重定义。

**[P1] 顺带发现的真 bug**：缓存页代码里已写「再点已选行 → 取消选中」（点击分支有 toggle 逻辑、注释承诺「再次点击取消选中」），但写回处 `if select.is_some()` 守卫把 `None` 静默丢弃——取消语义是死代码，点击已选行实际毫无反应。测试全绿但行为与注释相反，典型测试盲区逃逸。

其余全部 `selectable` 调用不受害：均为 ComboBox 弹层瞬时项（选完弹层即关），无残留问题。

## 2. 语义定义（canonical）

**列表选中态 = 页内临时操作焦点**，不是持久对象状态。它驱动该列表下方的操作按钮（编辑 / 删除 / 上移 / 下移 / 删除所选），焦点离开即失效——用户可能随时切走注意力（换 tab、调其他设置、点空白），此时按钮操作目标应视为放弃。

面板隐藏重开（托盘显隐）不在此语义内：那不是「离开页面」，选中保留（现状不变）。

## 3. 行为规格：四条取消通道 + 豁免清单

### 3.1 取消通道（三列表统一）

| # | 通道 | 行为 |
|---|---|---|
| C1 | 再点已选行 | 取消选中（toggle-off）；再点未选行 = 换选（不变） |
| C2 | 点面板空白区 | 取消选中。空白区 = 面板窗内所有非控件区域（内容下方大块空白、卡片间衬、行间缝）；见 §4.2 实现方案与回退 |
| C3 | 切换 tab | 清除**全部三处**选中（含不可见 tab 的遗留选中——「切换 tab 也无法消除」的忠实实现：选中不得跨 tab 存活） |
| C4 | 同 tab 改其他设置项 | 清除选中。含该页全部非列表控件值变更：勾选、拖动、数字步进、文本输入、下拉、色值、恢复本页默认工具条；背景图片经文件对话框的回执写回（`BgImagePicked` 事件）视为同 tab 控件变更，同样清除 |

**无键盘通道**：不加 Esc / 方向键（用户明示否决，纯多此一举）。

### 3.2 列表自身操作豁免（不受 C4 误伤）

列表自己的按钮与流程**维持现语义**，不触发 C4：

- 删除所选 → 清除选中（现行为）
- 上移 / 下移 → 选中跟随移动行（现行为）
- 新增 / 编辑确认（行编辑模态 OK）→ 选中新行 / 该行（现行为）
- 双击行 → 打开编辑器且该行保持选中（toggle 实现须保证双击净效果 = 选中 + 开编辑器，见 §4.3）

### 3.3 缓存页特例：刷新与下标漂移

缓存「刷新」重扫条目：条目集合**身份不变**（名称 + 路径逐项一致）则保留选中；身份变更（增删 / 重排）则清除——防下标漂移让蓝框指错行。承 D-87 的精神（删除载荷已用 path 身份键防漂移，本条把同样的防御补到选中高亮本身）。

### 3.4 行为矩阵汇总

| 动作 | 选中态 |
|---|---|
| 点未选行 | 选中该行 |
| 再点已选行 | **取消**（C1，缓存页死写回就此修复） |
| 点空白区 | **取消**（C2） |
| 切 tab | **三处全清**（C3） |
| 同 tab 改其他控件 | **清**（C4） |
| 列表：删 / 移 / 编辑确认 / 新增 | 现语义（§3.2） |
| 双击行 | 选中保持 + 开编辑器 |
| 缓存刷新（身份不变 / 变更） | 保留 / 清 |
| 面板隐藏重开 | 保留（范围外，现状） |
| Esc / 键盘 | 无（明示否决） |

## 4. 实现要点

### 4.1 三态写回（修死写回的根本法）

现写法 `let mut select: Option<usize> = None;` 用 `None` 兼作「本帧无点击」哨兵与「取消」值，导致写回守卫必须吞 `None`——这就是缓存页死写回的根源。改为三态：`无点击 / 选中(i) / 取消` 分离表达，写回仅在「本帧确有点击」时执行。三列表统一此写法。

### 4.2 空白区捕获（C2）

主案：面板根在内容之前分配整窗 rect（`Sense::click()`）作背景捕获——egui 后注册者 hit-test 优先，所有真实控件天然压住它，点空白才落网；行间缝、卡片衬、内容下方全部覆盖。**风险**：与 ScrollArea 拖拽滚动的兼容性（背景捕获可能截胡拖拽）须 headless 测试验证；若截胡，回退方案 = 仅捕获内容下方剩余 rect + 卡片间衬（放弃 5px 级行间缝，实际难点是内容下方大块空白，主案回退都覆盖）。

### 4.3 双击与 toggle 的次序

行响应若本帧 `double_clicked()` 则跳过 toggle（保持选中）直接走编辑分支——避免「第一帧取消、第二帧重选」的中间闪烁，净效果与 §3.2 一致。

### 4.4 C4 的 funnel：清选中 + 防抖落盘合流

三列表所在页的**非列表控件**写回点，统一从 `mark_settings_dirty(session)` 换到「清三处选中 + 防抖落盘」变体（一个 funnel，机械替换，可 grep 审计）；列表自身操作与行编辑确认保留原通道（§3.2 豁免）。`mark_settings_dirty` 本体签名不动（其余 tab 65 处调用面不受牵连）。其他 tab（样式 / VAD / 日志等）无列表选中，不需要换——能改到那些控件必然先经 C3 清过。

### 4.5 边界

- C1 与 C4 同帧冲突（点了行又拖了滑块）：C4 的清在后渲染分支执行即幂等，终态一致。
- 行编辑模态打开中点空白：模态窗在顶层不受影响，选中照清；模态 OK 确认后按 §3.2 重选中，自洽。
- 选中下标越界（列表外力变更）：渲染侧本就只与 `0..count` 比较，不高亮不 panic，不变。

## 5. 测试缝与矩阵

**缝**：复用既有 headless UI 测试缝（`egui::Context::default()` + 手动 pass 驱动 + 指针模拟 + 选中态断言）——panel 各页与 D-119/D-120/D-121 均此先例，**零新缝**。只测外部行为（点击序列 → 选中布尔 / 编辑器开关），不测内部 helper。

| # | 用例 | 断言 |
|---|---|---|
| T1 | 三列表各自：点行 → 选中；再点同行 | 选中 → 取消（**死写回回归主断言**） |
| T2 | 点行 A → 点行 B | 选中 B（换选不回归） |
| T3 | 选中 → 点空白区 | 取消（含滚动区共存：拖拽滚动不被背景捕获截胡） |
| T4 | 选中 → 切 tab → 切回 | 全程取消 |
| T5 | 选中 → 改同 tab 其他控件 | 取消 |
| T6 | 列表操作：删 / 上移 / 编辑确认 / 新增 | 选中跟随符合 §3.2（防 C4 误伤回归） |
| T7 | 缓存刷新：条目身份不变 / 变更 | 保留 / 清 |
| T8 | 双击行 | 编辑器开且行保持选中 |

基线滚动值随新增用例上浮；本包零契约改动（lt-proto 不动，PROTO_VERSION 不变）；零 i18n 改动（无新文案）。

## 7. 裁决留痕（2026-09-30，用户四答）

- **Q1 取消通道**：再点已选行 **和** 点任意空白处均取消；**切 tab 也要取消**；**选中期间改同 tab 其他选项也取消**；**不加键盘取消**（用户原话「纯纯多此一举」）。→ 落为 C1~C4。
- **Q2 切 tab 是否清空**（本席推荐不清空、以 C1 兜底）：**用户推翻推荐，拍板切 tab 清**——选中是临时焦点，不是该跨页保留的状态。本档按用户裁决执行，非偏离。
- **Q3 范围**：三个列表全修。
- **Q4 流程**：按 Matt Pocock 流程逐步走——grilling（已闭合）→ 本定稿（docs 提交 + D-123 登记）→ `/to-spec` 规格 issue（ready-for-agent）→ 单会话活**不拆单**（workflow §1「多会话大活才拆」）→ 等用户明示开工令 → `/implement`。
