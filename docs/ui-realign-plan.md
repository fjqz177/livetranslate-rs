# GUI 对齐原版改造方案（UI Realign Plan）

> 依据：2026-09-06 同机实测走查。同一台机器（Windows 10 / 2560x1600 / DPI 150%）先后运行 Python 原版（`LiveTranslate/main.py`，PyQt6）与 Rust 版（`target/release/livetranslate.exe`），逐窗口截图比对，并对存疑处回读双方源码交叉验证。
> 证据截图：`docs/ui-audit/`（文件名 `01_py_*` = 原版，`2x_rs_*` = Rust 版，`30_py_readme_running_zh.png` = 原版运行态官方效果图）。

---

## 0. 结论（TL;DR）

Rust 版 GUI 的问题不是"细节没抠"，而是三个方向性偏差：

1. **控制面板的信息架构整个跑偏**：原版是"顶部 7 个 Tab + 浅色 Windows 原生风格 + 高密度表单"（535×781 逻辑尺寸）；Rust 版做成了"左侧导航 7 项 + 深色卡片风 + 低密度大标题"（935×697 逻辑）。Tab 划分、命名、主题、密度四样全不同，原版用户的使用记忆完全失效。
2. **页面覆盖有缺有溢**：原版的「样式」Tab（主面板外观）、「基准测试」Tab、「更新日志」Tab 在 Rust 版中不存在；Rust 版自创的「常规」「诊断」页在原版中不存在。功能入口对不上。
3. **主面板（悬浮窗）与托盘的功能入口不全**：主面板缺「隐藏」按钮（7 缺 1）；模型下拉显示 `default` 而非真实模型名；托盘菜单只有 5 项（原版 12 项，缺字幕窗口开关/字幕鼠标穿透/显示日志/翻译模型/目标语言/语言提示/导出共 7 项入口）。

本方案给出逐项对照的差距清单和五个施工阶段，每个阶段带可验收标准。**核心原则：以原版实机行为为唯一规范（1:1），先结构后皮肤，砍掉原版没有的自创功能。**

---

## 1. 实测方法（可复用的验收基础设施）

本次走查沉淀了一套对两个版本都适用的自动化截图/交互手段，直接作为后续每个阶段的验收工具：

| 手段 | 用途 | 备注 |
|---|---|---|
| `EnumWindows` + 窗口标题枚举 | 列出两版进程的顶层窗口清单 | PyQt 主面板是 `WS_EX_TOPMOST|TOOLWINDOW|NOACTIVATE`，不会出现在常规 Alt-Tab；egui 窗口有 UIA 树但内容自绘 |
| `PrintWindow` (flag=0, DPI-aware) | 抓窗口整窗位图 | **对 PyQt 可靠；对 egui（GPU 渲染）会抓到旧帧**，验收 Rust 时必须用全屏截图 |
| 全屏截图 + 物理坐标换算 | egui 窗口走查 | 注意 ClientToScreen 与窗口坐标差 (边框 11, 标题栏 45)@150%DPI |
| `SetCursorPos`+`mouse_event`（SendInput） | 点击（含 NOACTIVATE 窗口） | `PostMessage` 合成消息对 Qt 无效，不要用 |
| UIA（`get_app_state`） | Qt 窗口控件树读取与 AXPress 点击 | PyQt 控制面板的 tab/按钮可直接 UIA 点击；egui 无 UIA 树 |

脚本已在会话中验证，无需入库；验收时按 §5 各阶段的"并排走查清单"执行即可。

## 2. 差距清单

评级：P0 = 结构性跑偏，必须改；P1 = 功能入口缺失，对齐原版必需；P2 = 观感/细节。

### 2.1 控制面板（P0，最大问题）

**原版结构**（`control_panel.py`，实拍 `02~08` 截图）：
- 顶部 Tab：`VAD / ASR`、`翻译`、`样式`、`字幕`、`基准测试`、`缓存`、`更新日志`（7 个）
- 浅色 Windows 原生控件（系统色按钮/下拉/滑条），QGroupBox 分组 + QFormLayout 两列表单，标签左对齐、控件右列统一宽度、几乎无说明文字
- 窗口 535×781 逻辑（802×1171 物理@150%），页面可滚动

**Rust 现状**（实拍 `21_rs_panel_general.png` 等）：
- 左侧导航：`常规`、`翻译`、`识别`、`字幕`、`数据与存储`、`诊断`、`关于`
- 深色卡片风：每项一层卡片 + 页头大标题 + 副标题说明 + 分组标题，密度约为原版 1/3
- 窗口 935×697 逻辑（1402×1046 物理）

**逐 Tab 差距**：

| 原版 Tab | 内容 | Rust 现状 | 动作 |
|---|---|---|---|
| VAD/ASR | 引擎/语言提示/设备/FunASR 模型/补零/**音频/麦克风/下载源/界面语言** + VAD 模式/两滑条 + **时间参数组**（最短/最长语音、静音模式+时长、增量识别+间隔） | 「识别」页有引擎/设备/VAD/时间参数（`vad.rs`），但**下载源、界面语言**缺位；引擎可用性绿字是自创增强（可留） | 重排为原版布局；补下载源、界面语言 |
| 翻译 | 模型配置列表（`>>> 名称`+URL+model）+ 添加/编辑/复制/删除 + 系统提示词（预设下拉+全文框）+ 模型连接超时 | 「翻译」页有同构内容（模型列表/按钮/提示词/超时） | 主要换布局皮肤；核对 ModelEditDialog 字段与原版一致（原版含代理/价格/上下文数/禁用思考/流式/JSON/system 合并/高级参数覆盖/extra_body） |
| 样式 | **主面板外观**：预设下拉+恢复默认+重置窗口位置；容器颜色/不透明度、头部颜色/不透明度、圆角；原文字体/字号/颜色、译文字体/字号/颜色、时间戳颜色；窗口透明度 | **不存在**（Rust 把"字幕窗"的样式放进了字幕页，主面板样式整个丢失） | **新建样式页**，1:1 原版字段；接入主面板渲染 |
| 字幕 | **字幕窗**：窗口宽度/行间距/颜色/不透明度/圆角/背景图片(选择·清除)/自动隐藏(5 秒 0=禁用)/隐藏动画(淡入淡出/时长)/鼠标穿透 + 文字行列表（启用|类型|字体 字号|颜色|对齐|轮廓 + 添加/编辑/删除/▲/▼）+ 恢复默认 | 「字幕」页字段基本齐，但文字行默认**未勾选**（原版默认勾选）、布局是卡片式 | 换布局；文字行默认启用状态对齐原版 |
| 基准测试 | 源语言/目标语言下拉 + 「测试全部模型」按钮 + 大结果区 | **无此页**；仅识别页页头有一个「性能基准…」按钮开独立工具窗（`bench.rs`） | 新建基准测试 Tab，工具窗能力并入 |
| 缓存 | 转录持久化（自动保存 checkbox + 打开转录文件夹）+ 模型缓存列表（总计+逐项大小）+ 打开模型文件夹 + 删除全部并退出 | 「数据与存储」页有全部字段（+自创"删除指定模型"） | 换布局；删除指定模型可作为增强保留 |
| 更新日志 | 富文本更新日志（日期大标题/粗体/代码样式） | **不存在**（关于页只有版本号） | 新建更新日志 Tab；数据源用原版 i18n/资源中的 changelog；egui 用 Markdown-ish 渲染 |
| （无） | — | 「常规」页：界面语言/深浅色主题/开机自动启动/启动时隐藏悬浮窗/减少动态效果/窗口布局/导入导出设置 | **整页删除**：界面语言归位 VAD/ASR Tab；重置窗口位置归位样式页；其余为自创功能，P2 再议 |
| （无） | — | 「诊断」页：平台能力/引擎/网络/存储路径/复制诊断摘要 | **整页删除**或并入「关于」折叠区（P2 决策） |

### 2.5 字幕窗（P2，强依赖 M3）

- 两版空态都不可见（原版默认 5 秒自动隐藏 + 无内容透明；Rust 一致），无对照意义。
- Rust 字幕窗配置字段已齐（宽度/行距/颜色/透明度/圆角/背景图/自动隐藏/动画/穿透/文字行列表）。
- 文字行默认启用状态需对齐（原版默认勾选原文+译文两行）。
- 真实效果（描边、居中、多行换行、进场动画）待 M3 事件接通后按原版 `zh.png/en.png` 效果图并排验收。

### 2.6 明确不改的（边界）

- 主面板 7 信号驱动、50ms 轮询、拖动/穿透等已实装的机制不动。
- M3（翻译事件流）不在本方案内；本方案完成后字幕流/主面板字幕区仍无真实数据，属预期。
- 自创增强（引擎可用性绿字、删除指定模型、诊断摘要）不删除代码，只移出主路径，收进「关于」页折叠区或保留为隐藏入口。

## 3. 技术路线决策

**问题：egui 能否做出"原版观感"？** 能近似到"并排看不出结构差异、观感统一"的程度，但无法 100% 复刻原生控件质感（原生子菜单动画、系统字体渲染微差）。替代路线均不可取：换 Qt 绑定违背 Rust 重写初衷；换 WebView 前端违背单 exe/轻量分发目标。

**决策：保留 egui，做三层对齐——**

1. **布局层**：控制面板从左侧导航改为顶部 `Tab` 行（egui `TabBox`-式自绘或 `ui.selectable_strip`），页面容器改 QGroupBox 式 `Frame`（细边框+分组标题嵌在边框上）+ 两列 `Grid`（左标签右控件），控件右列固定宽度；窗口默认尺寸改为 535×781 逻辑、内容 `ScrollArea`。
2. **主题层**（`style.rs` 集中改造）：控制面板切换为浅色 token（Windows 系统色系：窗口 #F0F0F0、控件白底、边框 #D9D9D9、选中 tab 白底黑字、hover 浅灰、强调色 #0078D4 滑条/勾选框）；主面板/日志窗维持深色。**按窗口分主题**：egui 全局单一 style，需要在 Panel/Overlay 各自的绘制入口用 `ui.style_mut()` 覆盖或 `set_visuals` 按窗体切换（两窗本就是独立 egui Viewport，天然可分）。
3. **字体层**：全全局注册 Microsoft YaHei（中文）+ Consolas（状态行/日志等宽数字），统一字号 token（原文 11pt/译文 14pt 对应逻辑像素）。

**工作量重心**：`crates/lt-ui/src/windows/panel/`（重排 7 页 + 删 2 页 + 新建 1 页）、`style.rs`（双主题 token）、`overlay.rs`（补隐藏按钮/模型名/去占位/字幕流配色）、`tray.rs`（全量菜单 + 事件路由）、`app.rs`（启动单开 + 向导接线）。

## 4. 施工计划（五阶段，顺序执行）

> 每阶段 = 独立 commit + 验收走查（用 §1 方法与原版并排截图对比）。阶段内条目均为可独立验证的最小改动。

### Phase A：控制面板结构对齐（P0，最大块）

1. 骨架：左导航 → 顶部 7 Tab；页容器/分组框/两列表单三种布局原语（`group_frame`、`form_row`）落地，供 7 页共用。
2. 浅色主题 token 应用到控制面板 viewport；主面板保持深色，验证双主题隔离。
3. 逐页迁移（保持现有 Cmd/Settings 数据通路不变，只动布局）：
   - VAD/ASR ← 现识别页（补下载源、界面语言；时间参数组按原版顺序）
   - 翻译 ← 现翻译页（含 ModelEditDialog 字段核对清单）
   - 字幕 ← 现字幕页（文字行默认勾选修复）
   - 缓存 ← 现数据与存储页
   - 样式 = **新建**（字段按 2.1 表；先接真实渲染的仅窗口透明度/圆角/头部色，其余随主面板 P1 通路）
   - 基准测试 = **新建**（迁移 `bench.rs` 能力进 Tab，源/目标语言 + 测试全部模型 + 结果区）
   - 更新日志 = **新建**（changelog 资源 + 渲染）
4. 删除常规/诊断导航项（界面语言归位、重置窗口位置归位样式页；autostart/诊断摘要移入关于页或暂存）。
5. 窗口默认尺寸 535×781、可滚动、可调整。

**验收**：7 Tab 名称顺序与原版一致；每 Tab 控件清单 diff（逐字段核对表随 PR 附）；浅色主题与原版截图并排无明显结构差异；主面板主题不受影响。

### Phase B：主面板对齐（P0-P1）

1. 头部补「隐藏」按钮（7/7，行为=隐藏悬浮窗，托盘可恢复）；按钮顺序/文案与原版一致。
2. 模型下拉显示 active 模型真实 display name。
3. 删除 `waiting for audio...` 占位。
4. 字幕流渲染配色/格式对照 `30_py_readme_running_zh.png` 逐项对齐（[ts] 灰、[lang] 标签、原文行、`> ` 译文行、ASR/TL 耗时标注；紧凑模式隐藏 ts 与耗时的规则核对）。
5. 样式页数据通路：容器/头部颜色+不透明度、圆角、字体字号 → 主面板绘制。
6. 紧凑模式参数复测原版（完整 500↔紧凑 200 逻辑高度，紧凑下按钮集与内容行规则）并对齐。
7. 字体 token 统一（YaHei + 状态行等宽）。

**验收**：两版主面板同屏并排，按钮行/行2/模型行/电平/状态行逐项一致；喂假事件后字幕流版式与 README 效果图一致。

### Phase C：托盘 + 日志窗 + 启动流（P1）

1. 托盘全量 12 项：补字幕窗口开关（checkbox）、字幕鼠标穿透（checkbox）、显示设置、显示日志、悬浮窗▶（显示悬浮窗/隐藏悬浮窗/…按原版）、翻译模型▶（切换活动模型）、目标语言▶、语言提示▶、导出到文件▶（TXT/SRT/…）；退出确认保持。
2. 日志窗：托盘入口 + 底部控件（自动滚动/显示 DEBUG/清除）与配色对齐。
3. 启动流：启动仅开主面板（控制面板隐藏）；托盘「显示设置」/主面板「设置」toggle 控制。

## 5. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| egui 浅色主题与原生质感差距被用户感知 | Phase A/D 返工 | Phase A 先交骨架截图给用户确认方向，再铺量 |
| 样式页数据通路牵动 overlay 绘制 | Phase B 范围膨胀 | Phase B.5 只接 4 个字段（透明度/圆角/容器色/头部色），字体字号随 M3 后统一调 |
| 基准测试并入 Tab 依赖 worker/探测通道 | Phase A 卡壳 | Tab 内先嵌现有 bench 工具窗能力，通道复用 M5.1 探测 |
| 更新日志富文本在 egui 的渲染降级 | 观感打折 | 日期标题+正文两级富文本即可，代码样式用等宽字体 token |
| 首启向导依赖下载链路稳定性 | Phase C 联调耗时 | 向导 UI 先行，下载失败路径复用 M5.1 已验证的错误处理 |
